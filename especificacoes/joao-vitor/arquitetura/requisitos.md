# Requisitos — EARS

Requisitos do Rastro (REQ-01 a REQ-89) escritos nos cinco moldes EARS (Mavin et al., 2009). Cada um tem um id estável (`REQ-xx`), que é citado nas fichas de tela, nos contratos e nos cenários de qualidade. Nenhum id foi renumerado: quando a auditoria dividiu um requisito composto, a segunda obrigação ganhou um id novo e aparece logo abaixo do original, com a nota "(divide REQ-xx)".

- **Molde**: U = ubíquo · E = evento · S = estado · I = indesejado · O = opcional. Todo requisito tem o sujeito "O SISTEMA" e uma única obrigação.
- **Origem**: de onde vem o requisito. FI-01 = Formulário de Ideação. AC-n = critério de aceitação da primeira fatia (FI-01 §11.2). Brief = README do repositório do grupo (`ddea-ufpb/rastro`). ADR = decisão registrada em `adr/`.
- **Verificação**: o teste que comprova o requisito (arquivo previsto · caso). `e2e/` são testes de interface do painel (Playwright + axe).
- **Módulo**: módulo do grupo que implementa o requisito (`ingestao`, `nucleo`, `consulta`, `saida`; ver o mapa em [README.md](README.md#mapa-para-os-quatro-módulos-do-grupo)). "todos" = requisito transversal.
- **Telas**: fichas em `../telas/` que citam o requisito. A coluna é gerada e conferida por `verificar.py` (diretiva 1); "—" = requisito sem tela, coberto por ADR, contrato ou cenário de qualidade.

Convenções usadas no texto:

- "lote ativo" é o lote indicado por `PublicacaoAtiva` para a fonte.
- Valores monetários são inteiros em centavos (`*_centavos`).
- Erros da API seguem `application/problem+json` (RFC 9457) com o campo `codigo`.
